## 原理：

开发者往往为了避免重复代码的编写，会把实现某种功能的一些代码汇总成一个文件，在搭建网站需要使用该功能时通过文件包含函数调用功能文件。

而文件包含漏洞则是通过利用网站允许的文件包含函数来调用用户自己定义的恶意文件从而使其中的恶意代码以脚本格式执行

eg:

比如说我们有一个恶意文件1.txt由于后缀名绕过成功上传到了网站，如果直接访问1.txt就会导致文件以txt格式执行，无法让其中的恶意代码发挥作用，此时通过文件包含漏洞，比如include file="1.txt",让1.txt文件被包含然后按照脚本格式执行，最后就会让其中的恶意代码执行

**实质就是通过文件包含函数把用户上传的恶意文件以脚本格式执行**



`#文件包含各个脚本代码`
`ASP,PHP,JSP,ASPX等`

`<!-—#include file="1.asp " -->`

`<!--#include file="top.aspx"-->`

`<c:import url="http://lthief.one/1.jsp">`-------包含远程网址的一个文件

`<jsp:include page="head .jsp" / >`------------包含本地的一个文件

`<%@ include file="head.jsp" %>`

`<?php Include ( 'test.php ' ) ?>`

## 产生条件：

要想成功利用文件包含漏洞进行攻击，需要满足以下**两个条件：**
1、Web应用采用include()等文件包含函数通过动态变量的方式引入需要包含的文件;
2、用户能够控制该动态变量。

php中引发文件包含漏洞的通常是以下四个函数：

(1) Require: 找不到被包含的文件时会产生致命错误(E_COMPILE_ERROR)，并停止脚本，如果在包含的过程中有错，比如文件不存在等，则会直接退出，不执行后续语句。；

(2) Require_once：与 include 类似会产生警告，区别是如果文件代码已经被包含，则不会再次被包含；

(3) Include：找不到被包含的文件时只会产生一个(E_warinng)，脚本将继续执行；

(4)include_once()
require_once() 和 include_once() 功能与require() 和 include() 类似。但如果一个文件已经被包含过了，则 require_once() 和 include_once() 则不会再包含它，以避免函数重定义或变量重赋值等问题。
（比较常见的还有这些函数：highlight_file()、show_source()、readfile()、file_get_contents()、fopen()、file()）

### 文件包含之伪协议利用:

伪协议的利用是基于文件包含漏洞的基础上的

每种脚本自己都支持一定的伪协议，伪协议的作用类似于脚本自带的函数，比如php脚本支持php://filter协议（用于读取文件源码），按照规定的格式提交参数就可以读取文件的源码。

因此伪协议的利用实质上还是文件包含漏洞，都是去指向一个文件然后对其进行某种操作
